# Known gaps and limitations

- **Observed Windows 11 blocker:** the owner’s personal PC with Smart App Control enabled blocks the unsigned `JLVoiceAsr.exe` worker. Hosted CI does not enforce that policy. A new unsigned ZIP or UI error fix does not resolve it; trusted publisher signing and testing under the enabled policy are required. No signing certificate/service is available yet. See [signing status](SIGNING.md).

- Hosted Windows CI passes package creation, deterministic state/audio checks, native edit-control Unicode/focus/clipboard checks, UI checks and a narrow paired CZ/EN CPU quality probe. It does not establish physical keyboard/microphone, modern Notepad/browser or representative hardware acceptance.
- No complete portable runtime/model package has been executed on a clean offline Windows 11 machine. The packaging script passes on a developer-tool-equipped hosted Windows runner; that does not prove clean-machine acceptance.
- **Owner speech-quality failure:** a Windows machine that permits startup completed dictation in approximately three seconds, but the owner reported unusable Czech output with repeated characters in Automatic and explicit Czech. The owner reports clear audio in Windows Sound Recorder; a later screenshot shows a discrepancy between Last transcript and the destination text. The actual JL Voice captured audio has not yet been confirmed by playback. Use the opt-in in-memory audio playback check in TESTING.md before attributing this to the model or microphone.
- Base q5_1 is an unaccepted experimental candidate. A six-recording paired CPU probe found inadequate Czech error rates for both Base and Small. General Czech/English quality, punctuation, silence hallucinations and mixed-language usability remain unaccepted. Single-recording language switching is not specifically implemented.
- Recording is bounded to 90 seconds, not arbitrary long-form dictation. Safe chunking and switch-aware processing remain needed.
- Worker-per-recording unloads the model but adds startup latency. Resident model trade-off has not been measured.
- Input dispatch checks foreground window and native focused-control handles, but browser DOM fields can share a native handle and focus can still race. Partial input may occur. Password-field detection/UI Automation targeting, elevated targets and supported-app behavior need implementation/verification before release.
- Fresh installs default to holding Caps Lock; existing saved shortcuts are preserved. Hold-state repeat/cancellation behavior has deterministic checks, but physical Caps Lock state preservation, low-level-hook consumption, rapid press/release, microphone failure and shutdown still need Windows keyboard/device stress tests.
- Microphone list is captured at startup. Devices disconnected/reordered while the app is running need better recovery and stable device identity.
- Settings changes are explicit and portable; saving requires a writable folder. Shortcut conflicts and malformed settings are reported. Brand themes and Czech/English UI pass hosted WPF rendering/font/compact-layout and bubble focus/timer checks; physical DPI, high-contrast, screen-reader and full keyboard acceptance remain unverified. Startup registration, dictionary, optional history and formatting profiles are not implemented.
- WPF uses software rendering to avoid a GPU rendering context. Hosted idle measurements do not establish CPU responsiveness, physical DPI/monitor behavior or memory acceptance on representative 8 GB hardware.
- No default history, model prewarming, persistent worker, cloud fallback or LLM. No grammar/postprocessing quality claims.
- Full-app monitor supplies sampled working-set/CPU and input-dispatch timings; the worker also supplies OS peak/CPU counters. Modern target-app insertion, cold-cache control and desktop responsiveness still require additional evidence.
- No signed executable, completed redistribution audit, production release, or benchmark-qualified minimum system requirements.
- Upstream MSVC builds emit warnings, including pointer/bool conversions in ggml backward-gradient helpers and ignored GCC pragmas. Source inspection places the reported conversion sites in gradient-building code; the inference smoke test passes, but this is not a comprehensive upstream warning audit. Review before release; no upstream patch is carried.

- NVIDIA app integration is a development test: owner microphone → cloud → original target insertion still needs hands-on acceptance. Cloud Auto is unverified and disabled; select Czech or English. Developer endpoint availability, quotas and continued free access are not guaranteed. Cloud does not resolve Windows blocking the unsigned main executable.

- Owner confirmed paced Unicode packet insertion corrupts text in Notepad, whereas explicit Copy → Ctrl+V preserves the app transcript. A transactional paste replacement is under test. Native HWND guards cannot distinguish browser DOM fields; clipboard restoration is conditional and can fail under Windows locks. Targets reading later than the 700 ms grace period remain an unverified compatibility risk.
- Owner also reported NVIDIA cloud with requested Czech returning inaccurate English text. The shared client sends cs-CZ; actual microphone audio and same-audio model comparison are still needed. Do not treat fixing insertion as fixing recognition accuracy.
